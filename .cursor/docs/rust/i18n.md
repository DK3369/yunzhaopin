# 后端 i18n（phpyun-rs）

原文：[phpyun-rs/docs/INTERNATIONALIZATION.md](../../../phpyun-rs/docs/INTERNATIONALIZATION.md)。

1. 接口 `msg` 必须是最终文案，不能把翻译 key 丢给客户端。
2. 固定文案：`phpyun-rs/locales/{en,zh-CN,zh-TW}.json`（编译期嵌入）。**只补本接口用到的编号**，不要把 Vue 1.6 万 key 整包打进 Rust。
3. 后台可改的分类/地区：库表 `phpyun_dict_i18n` + 启动加载内存，不要请求时查字典表拼文案。
4. 语言顺序：`?lang=` → `Accept-Language` → Cookie `lang` → 默认。`en-US` 归一成 `en`。后台 cookie 是 `admin_lang`，前台是 `lang`，互不污染。
5. 业务代码不要 `if lang == "en"` 拼字符串；走 i18n / 字典服务。
6. 翻译 key 要稳定，不要用中文原文当 key。

## 四层（不要合成一套文件）

| 层 | 干什么 |
|---|---|
| Nuxt 编号包 | 按钮、表头、`lc()`。`web/apps/{admin,site}/i18n/locales/{zh,en}.json` |
| Rust `msg` / `*_n` 枚举 | 错误文案、支付方式、订单类型、支付状态等。码 → 编号 key → `enum_labels::label`（`current_lang()`） |
| `dict_i18n` | 职位/行业/地区等运营可改分类名 |
| Packed | 库里历史 blob：套餐名、日志 `content`、`pay_remark`（key、中文或拼接）。`web/layers/base/app/utils/packedText.ts`，后台 `packedLog` / 前台 `runPackedTranslate` |

## 存什么

- **码/数字**：`company_order.order_type` / `type` / `order_state`。读时翻成当前语言。
- **运营配置中文**（套餐名）：库保持原样，展示 `packedLog`。新写入尽量存编号 key（过期套餐 `admin_user_company_00297`）。
- **不翻**：公司名、用户名、采集 JD、地址、管理员自由备注。

入口：[enum_labels.rs](../../../phpyun-rs/crates/products/recruit/services/src/enum_labels.rs)。getCache 的 `source` / `user_sex` / `com_sex`、SEO 模块名与变量名也走这里。广告位 `place_n`（非 PC/WAP 的「未定义」）、默认积分名、问答举报原因、采集 `last_msg` 同样走编号 key / `label()`，不要 `if lang` 拼句。

这和 PHP 模板 `{yun:}t key='wap_00439'` / `data/lang/auto/*.php` **不是同一套**。改 Nuxt 文案走 `web/` 的 i18n；改 Rust 报错与枚举标签走 `locales/` 与 `rust-i18n`。不改 `uploads/` PHP。
